### 2026-08-07 — MM-59: Live price poller → Kafka → SQL latest-price cache; API/chart read SQL, never yfinance
- **Done:** Root-caused a live production hang: `GET /exposure` (and the price-chart endpoint) called `yfinance` live, synchronously, on the request path. The route is `async def` but everything inside was blocking sync I/O with no `await`/threadpool offload, so one slow/hung `yfinance` call froze the *entire* asyncio event loop -- reproduced live, `/health` (a trivial static-response `async def`) stopped responding too. `docs/DATA_SOURCES.md`/`docs/ARCHITECTURE.md` already documented the intended design (prices flow `Kafka → SQL`; daily/EOD data is batch-loaded, only intraday ticks stream) -- MM-32 ("Live feed adapter path... sharing the same topic") was marked Done but the live feed was never actually wired to publish onto Kafka on an interval; it was just called directly by the API. This story delivers that for real: new `streaming/live_feed_poller.py` (`make live-feed-poller`) publishes ticks for the curated universe onto the existing `market.prices` topic on a **fixed interval** (`LIVE_FEED_POLL_INTERVAL_SECONDS`, default 60s -- deliberately no volatility-threshold gating, kept simple). The existing Event Agent consumer (`streaming/event_agent.py`) now unconditionally upserts a new `latest_prices` SQL table (`LatestPriceORM`) on **every** tick, as the literal first line of `handle_price_message`, before any dedup/threshold branch -- most ticks never cross the shock/spike threshold, so upserting after those checks would have meant the table almost never updated. `/exposure` (`api/exposure.py`) and the price-history/chart endpoint now read only `persistence.queries.latest_prices`/`price_history` -- zero `yfinance` calls anywhere on a request path, ever. `compute_mtm` already raised `PricingError` for a ticker missing from the price dict, so a not-yet-polled ticker falls through the existing `_unavailable(...)` fallback with no new branch needed. Also auto-wired an idempotent `backfill_price_history` into `persistence/batch_loader.py`'s `run_batch_load` (skips any ticker already holding ≥5 rows in `price_history`) so the chart isn't visibly sparse for weeks while `price_history` slowly accumulates day by day -- a manual one-off backfill step was rejected as something that's easy to forget and would leave the chart looking broken indefinitely.

Backfill auto-wired into the recurring `make batch-load` rather than a separate manual command, specifically because "remember to run this once" steps get skipped.
